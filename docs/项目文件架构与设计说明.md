# AvaloniaTodoApp 项目全文件架构与设计说明文档

本文档全面梳理 **AvaloniaTodoApp** 项目中每一个文件的职责、定位及其背后的架构设计原因。

---

## 一、 架构总览与核心设计哲学

本项目是基于 **.NET 8 + Avalonia 11** 构建的现代化跨平台桌面应用，业务场景涵盖“**半导体芯片 3D 检测上位机看板**”、“**生产待办工单管理**”与“**工业级运行与故障日志**”。

整个项目采用了标准的 **MVVM (Model-View-ViewModel)** 架构与 **依赖注入 (IoC/DI)** 模式，并在前端（如 Vue 3 / Web）全栈开发体验和桌面原生工业稳定性之间做出了深度融合设计。

### 🌟 前端全栈视角架构映射表

| 桌面端概念 / 本项目技术实现 | 前端 (Vue 3 / React) 对等概念 | 核心设计作用 |
| :--- | :--- | :--- |
| **`ViewLocator` + `ContentControl`** | `Vue Router` 路由映射 + `<router-view>` | 根据 ViewModel 类型反射找到对应 View 进行渲染 |
| **`_viewCache` 字典 + 多通道常驻** | `<keep-alive>` 页面缓存 | 保留 3D WebGL 上下文，切换页面零销毁、零黑屏 |
| **`ObservableObject` + `[ObservableProperty]`** | Vue 3 `ref()` / `reactive()` | 响应式状态管理，属性变更自动推送 UI 重绘 |
| **`[RelayCommand]`** | 事件处理函数 (`@click="handleClick"`) | 解耦 UI 点击事件与业务逻辑，支持异步与参数传递 |
| **`StreamGeometry` (`Icons.axaml`)** | SVG 内联图标 / IconFont | 原生 GPU 硬件光栅化，零第三方依赖，自适应明暗模式 |
| **`JsonTodoStorageService` (原子替换)** | 本地持久化 (`IndexedDB` / 本地文件) | `.tmp` 写入后原子替换，加损坏隔离备份防断电损坏 |
| **`TaskCompletionSource` 合并队列** | 请求合并 / 防抖节流 (`debounce`) | 高频写入单写入循环，避免磁盘并发冲突与性能卡顿 |

## 三、 程序启动入口与生命周期管理

### 1. [`Program.cs`](file:///Users/zhouenbo/AvaloniaTodoApp/Program.cs)
- **文件职责**：应用程序操作系统级静态启动入口点（`Main` 方法）。
- **核心逻辑**：
  1. `SetupGlobalExceptionHandling()`：全生命周期全局崩溃防御底座。
     - 监听 `AppDomain.CurrentDomain.UnhandledException`：拦截主线程未捕获致命异常并记录致命日志。
     - 监听 `TaskScheduler.UnobservedTaskException`：拦截后台 `async/await` 遗漏导致的后台任务异常，调用 `e.SetObserved()` 阻止进程被操作系统意外强杀。
  2. `LogHelper.InitLogger()`：最优先启动 Serilog 日志基础设施。
  3. `BuildAvaloniaApp()`：构建 Avalonia 运行时，配置字体（`WithInterFont()`）、平台探测（`UsePlatformDetect()`）与桌面内嵌浏览器（`UseDesktopWebView()`）。
- **设计原因**：桌面端工业软件极忌“闪退无痕”。把全局异常拦截与日志初始化提升到 `AvaloniaApp` 初始化之前，保证哪怕在图形引擎初始化失败时也能把堆栈信息准确记录到磁盘日志中。

### 2. [`App.axaml`](file:///Users/zhouenbo/AvaloniaTodoApp/App.axaml)
- **文件职责**：Avalonia 全局 XAML 应用声明。
- **核心组件**：
  - `<local:ViewLocator />`：全局数据模板路由解析器。
  - `<FluentTheme />`：微软 Fluent Design 视觉体系。
  - 合并字典 `<ResourceInclude Source="...Icons.axaml" />`：全局注入矢量图标。
  - `<TrayIcon.Icons>`：系统原生托盘配置，带有托盘右键菜单（显示主界面、关于与更新、退出程序）。
- **设计原因**：通过声明式 XAML 构建原生跨平台托盘，无需为 macOS、Windows 单独编写平台特定 P/Invoke 代码；同时统一注入全局主题和图标资源。

### 3. [`App.axaml.cs`](file:///Users/zhouenbo/AvaloniaTodoApp/App.axaml.cs)
- **文件职责**：应用生命周期与依赖注入 (DI) 组合根 (Composition Root)。
- **核心功能**：
  - `ConfigureServices()`：统一注册单例基础设施（`JsonTodoStorageService`、`UpdateService`）与业务 ViewModel（`ChipInspectViewModel`、`TodoViewModel`、`DeviceLogsViewModel` 为单例，主窗口与关于窗口为 Transient）。
  - `ShowMainWindow()` / `ShowAboutWindow()` / `ExitApp()`：托盘与主界面调度。
  - 退出清理：监听 `desktop.Exit` 事件，显式释放 `IDisposable` 资源；在退出前调用 `vm.FlushAsync()` 确保磁盘写入完成。
- **设计原因**：遵循单一职责与控制反转原则。将所有服务的生命周期在启动阶段统一部署，彻底消除了各层代码随处直接 `new` 具体实现所带来的紧耦合与难以单元测试的缺陷。

### 4. [`ViewLocator.cs`](file:///Users/zhouenbo/AvaloniaTodoApp/ViewLocator.cs)
- **文件职责**：MVVM 视图定位器与路由组件解析器（实现 `IDataTemplate`）。
- **核心机制**：
  - 约定优于配置：将 ViewModel 名称中的 `ViewModel` 替换为 `View`（例如 `ChipInspectViewModel` 自动映射到 `ChipInspectView`）。
  - **`_viewCache` 缓存字典机制（等价于 Vue `<keep-alive>`）**：首次解析出 View 后缓存其实例，后续切换直接返回缓存实例。
- **设计原因**：在 Avalonia 默认的 ViewLocator 中，每次切换数据上下文都会重新 `new` 对应的 View，这会导致内嵌的三维 WebGL 画布（Three.js）上下文被不断销毁重建而导致严重的白屏/黑屏以及显存泄漏。引入缓存字典后，完美实现了跨模块切换时的保活。

## 四、 领域模型与核心服务层 (Models & Services)

### 1. [`Models/TodoItem.cs`](file:///Users/zhouenbo/AvaloniaTodoApp/Models/TodoItem.cs)
- **文件职责**：纯领域数据模型（POCO / Entity）。
- **属性定义**：`Guid Id`（全局唯一标识）、`string Title`（任务标题）、`bool IsCompleted`（是否完成）、`DateTimeOffset CreatedAt`（创建时间戳）。
- **设计原因**：
  1. 采用 `DateTimeOffset` 而非 `DateTime`：内置时区偏移量，在不同操作系统时区或数据跨时区同步时杜绝时间歧义。
  2. 纯数据模型与 ViewModel 分离：保持持久化实体干净，不受 UI 框架变更通知代码（如 `INotifyPropertyChanged`）污染。

### 2. [`Services/ITodoStorageService.cs`](file:///Users/zhouenbo/AvaloniaTodoApp/Services/ITodoStorageService.cs)
- **文件职责**：本地数据存储层抽象契约接口。
- **方法签名**：`LoadAsync()`、`SaveAsync(items)`、`StorageFilePath`。
- **设计原因**：依赖倒置原则（DIP）。上层业务只依赖接口契约，单元测试时可以随时注入内存 Mock（如测试用例中的 `FakeStorageService`），而无需触碰真实物理磁盘。

### 3. [`Services/JsonTodoStorageService.cs`](file:///Users/zhouenbo/AvaloniaTodoApp/Services/JsonTodoStorageService.cs)
- **文件职责**：基于 JSON 文件的企业级安全本地持久化实现。
- **核心安全机制**：
  1. **跨平台安全路径**：自动存储在操作系统的安全用户目录（Windows: `%AppData%/AvaloniaTodoApp/todos.json`，macOS: `~/Library/Application Support/AvaloniaTodoApp/todos.json`）。
  2. **异步原子写入 (Atomic Save)**：
     - 数据先完整写入 `todos.json.tmp` 临时文件；
     - 写入成功后再通过 `File.Move(..., overwrite: true)` 瞬间完成原子覆盖。
     - **杜绝由于系统断电、进程强制退出导致的文件被截断或写入半截 JSON 的致命 Bug**。
  3. **数据损坏自动隔离备份 (Corruption Quarantine)**：
     - 若反序列化发生异常，不静默清空或覆盖，而是将损坏文件备份至 `todos.json.corrupted.yyyyMMddHHmmss`。
  4. **线程互斥安全**：内置 `SemaphoreSlim(1, 1)` 异步锁，防止多线程并发读写竞争。

### 4. [`Services/IUpdateService.cs`](file:///Users/zhouenbo/AvaloniaTodoApp/Services/IUpdateService.cs) 与 [`Services/UpdateService.cs`](file:///Users/zhouenbo/AvaloniaTodoApp/Services/UpdateService.cs)
- **文件职责**：软件版本检测与在线更新元数据服务。
- **核心算法亮点 (`IsNewerVersion`)**：
  - 杜绝字符串字典序比较陷阱：在字典序中 `"1.10.0" < "1.9.0"`，会导致新版本无法提示更新。
  - 实现标准数值分段解析比对：支持去掉 `'v'` 前缀、按 `.` 拆分三段/四段数字逐位比对，保障升级检测绝对精准。
- **设计原因**：将版本比较逻辑封装为独立、无 UI 绑定的纯服务，并在测试工程中进行多达 10 余种边界值的全量单测覆盖。

### 5. [`Services/LogHelper.cs`](file:///Users/zhouenbo/AvaloniaTodoApp/Services/LogHelper.cs)
- **文件职责**：Serilog 工业级日志统一初始化与管理工具。
- **核心特性**：
  1. **双通道输出**：控制台（实时高亮用于开发调试）+ 磁盘文件（按天滚动归档）。
  2. **企业级保留策略**：毫秒级时间戳、单文件上限 10MB、最多保留 30 天日志、过期自动清理。
  3. **安全降级防御**：若系统 `%AppData%` 权限受限，自动降级至系统临时目录（`Path.GetTempPath()`），确保日志系统本身绝不崩溃。
  4. **跨平台一键打开目录**：识别 macOS（`open`）、Windows（ShellExecute 资源管理器原生兼容中文字符和空格）、Linux（`xdg-open`）。

## 五、 视图模型层 (ViewModels)

### 1. [`ViewModels/ViewModelBase.cs`](file:///Users/zhouenbo/AvaloniaTodoApp/ViewModels/ViewModelBase.cs)
- **文件职责**：所有 ViewModel 的统一抽象基类。
- **实现机制**：继承自 `CommunityToolkit.Mvvm.ComponentModel.ObservableObject`。
- **设计原因**：提供标准化的 `INotifyPropertyChanged` 与 `INotifyPropertyChanging` 实现。通过 C# 源代码生成器（Source Generators），使子类只需声明 `[ObservableProperty]` 即可在编译期自动生成属性通知代码。

### 2. [`ViewModels/MainWindowViewModel.cs`](file:///Users/zhouenbo/AvaloniaTodoApp/ViewModels/MainWindowViewModel.cs)
- **文件职责**：主界面路由外壳与全局宿主 ViewModel。
- **设计机制**：
  - `NavModule` 枚举：定义 3 大业务子模块（`ChipInspect`、`Todo`、`Logs`）。
  - `SwitchModuleCommand`：根据模块枚举切换路由，控制导航高亮态（`IsModuleChipInspect`、`IsModuleTodo`、`IsModuleLogs`）。
  - 依赖注入持有子模块单例：统一管理生命周期初始化 `InitializeAsync()` 与安全关停持久化 `FlushAsync()`。

### 3. [`ViewModels/TodoItemViewModel.cs`](file:///Users/zhouenbo/AvaloniaTodoApp/ViewModels/TodoItemViewModel.cs)
- **文件职责**：单个待办任务项的响应式包装。
- **属性与行为**：
  - `Title`、`IsCompleted`：响应式属性，勾选或修改时自动触发 `OnIsCompletedChanged` 分部方法。
  - `CreatedAtText`：根据系统当前 Culture 格式化输出易读时间（如 `09-11 14:30`）。
  - `StatusChanged` 事件：当单项完成状态改变时，主动通知外层父列表重新计算汇总与筛选。
- **设计原因**：实现 UI 元素与底层模型的解耦，提供双向映射方法 `FromModel()` / `ToModel()`。

### 4. [`ViewModels/TodoViewModel.cs`](file:///Users/zhouenbo/AvaloniaTodoApp/ViewModels/TodoViewModel.cs)
- **文件职责**：生产工单与待办任务业务的核心控制器。
- **核心算法亮点：自动合并写盘调度队列 (Auto-Save Coalescing)**：
  - **问题痛点**：若用户快速连续点击勾选 10 次，若每次都直接进行磁盘 I/O，会造成磁盘冲突与 IO 阻塞。
  - **解决方案**：
    - 采用单写入循环（Single Write Loop）模式。
    - 维护 `_isSaving` 与 `_hasPendingSave` 状态标记；当正在保存时，新的修改仅打上 Pending 标记并退出。
    - 当前次保存完成后，循环会自动抓取内存中的**最新快照**进行追加保存。
    - 结合 `TaskCompletionSource`，程序在关闭退出时调用 `FlushAsync()`，确保无论在何种并发修改状态下，最终一次状态绝对安全落盘。

### 5. [`ViewModels/AboutUpdateViewModel.cs`](file:///Users/zhouenbo/AvaloniaTodoApp/ViewModels/AboutUpdateViewModel.cs)
- **文件职责**：“关于与版本更新”独立弹窗 ViewModel。
- **功能**：异步调用 `IUpdateService.CheckForUpdatesAsync()`、显示新版本发布日志、调用跨平台默认浏览器打开下载地址、展示本地存储与日志绝对路径。

### 6. [`ViewModels/ChipInspectViewModel.cs`](file:///Users/zhouenbo/AvaloniaTodoApp/ViewModels/ChipInspectViewModel.cs)
- **文件职责**：3D 芯片检测看板 ViewModel。
- **功能**：提供看板标题、PLC 通信在线状态遥测、Three.js 引擎信息绑定。

### 7. [`ViewModels/DeviceLogsViewModel.cs`](file:///Users/zhouenbo/AvaloniaTodoApp/ViewModels/DeviceLogsViewModel.cs)
- **文件职责**：工业设备运行与系统日志界面 ViewModel。
- **功能**：绑定当前日志目录、滚动归档策略（31天循环滚动）与防崩溃状态，支持一键调起系统文件管理器。

## 六、 视图与呈现层 (Views & Resources & Assets)

### 1. [`Views/MainWindow.axaml`](file:///Users/zhouenbo/AvaloniaTodoApp/Views/MainWindow.axaml) 与 [`.cs`](file:///Users/zhouenbo/AvaloniaTodoApp/Views/MainWindow.axaml.cs)
- **文件职责**：主窗口 UI 布局与窗口行为拦截。
- **核心设计亮点**：
  1. **0 像素位移动态侧边栏**：左侧预设 `3px` 透明边框，激活状态点亮科技天蓝光条，彻底杜绝激活时的布局抖动。
  2. **彻底消除原生白闪 (Anti-White Flash)**：重写 Fluent 控件模板中的 `PART_ContentPresenter`，覆盖默认半透明白色按压态。
  3. **多通道常驻视觉树 (Keep-Alive View Tree)**：右侧工作区采用多个 `ContentControl` 通过 `IsVisible` 切换显示，而不是销毁重建。**确保 Three.js WebGL 与 WebKit 句柄始终存活，彻底解决页面切出切回时 3D 画布黑屏或刷新闪烁问题**。
  4. **窗口关闭常驻托盘拦截**：重写 `OnClosing`，默认 `CanClose = false`，点击窗口关闭按钮仅调用 `Hide()` 隐藏至系统托盘，防止误关；彻底退出时触发 `vm.FlushAsync()`。

### 2. [`Views/TodoView.axaml`](file:///Users/zhouenbo/AvaloniaTodoApp/Views/TodoView.axaml) 与 [`.cs`](file:///Users/zhouenbo/AvaloniaTodoApp/Views/TodoView.axaml.cs)

## 九、 总结：核心设计决策背后的思考

1. **为什么在桌面端采用前端思维的“组件路由+保活缓存”？**
   桌面应用尤其是嵌入 3D WebGL（Three.js）或复杂画布时，最容易因频繁的视图切换导致视觉上下文丢弃而黑屏。通过 `ViewLocator` 缓存与多通道常驻，兼顾了低内存占用与即时切页体验。
2. **为什么坚持数据原子写入（`.tmp` -> 重命名）与合并队列？**
   桌面客户端可能随时遭遇断电、死机或强制关机。直接覆盖文件（`File.WriteAllText`）极易产生空文件或非法 JSON。原子替换配合损坏隔离备份，彻底保障用户数据安全。
3. **为什么全部使用矢量 StreamGeometry 代替图片或第三方字体图标？**
   字体图标容易产生运行时字体丢失与渲染发虚问题，位图图标无法无损缩放。原生 `StreamGeometry` 直接交付 GPU 绘制，跨平台、高保真、零外部依赖。
